## 2. Підготовка проєкту та створення Dockerfile

У каталозі `~/lifedays-docker` підготовлено вихідний код застосунку (`app.py`, `calculator.py`, `VERSION`, `requirements.txt`, шаблони та стилі) і створено `Dockerfile`:

```dockerfile
FROM python:3.12-slim

WORKDIR /app

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    TZ=Europe/Kyiv

RUN groupadd --system web && \
    useradd --system --create-home --gid web web

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

COPY app.py calculator.py VERSION ./
COPY templates/ templates/
COPY static/ static/

USER web

EXPOSE 8000

HEALTHCHECK --interval=30s --timeout=3s --start-period=5s \
  CMD ["python", "-c", "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health', timeout=2)"]

CMD ["gunicorn", "--bind", "0.0.0.0:8000", "--workers", "2", "app:app"]
```

## 5. Відповіді на контрольні запитання

1. **Чим Docker-образ відрізняється від Docker-контейнера?**  
   Docker-образ (Image) — це незмінний (read-only) шаблон, який містить код застосунку, бібліотеки, залежності та налаштування середовища. Docker-контейнер (Container) — це запущений екземпляр (процес) на основі цього образу, який має власний ізольований шар для запису даних під час роботи.

2. **Яке призначення Dockerfile?**  
   Це текстовий файл без розширення, який містить послідовні інструкції для автоматизованого збирання Docker-образу (визначення базової ОС, копіювання файлів, встановлення залежностей, налаштування користувача та команди запуску).

3. **Чим відрізняються інструкції `RUN` та `CMD`?**  
   Інструкція `RUN` виконує команди **на етапі збирання образу** (`docker build`) — наприклад, встановлює пакети (`pip install`) і записує зміни у новий шар образу. Інструкція `CMD` задає команду за замовчуванням, яка виконується **при запуску контейнера** (`docker run`) — наприклад, запуск сервера `gunicorn`.

4. **Для чого використовується інструкція `WORKDIR`?**  
   Вона встановлює робочий каталог усередині контейнера (у цій роботі `/app`), у якому виконуватимуться всі наступні інструкції (`RUN`, `COPY`, `CMD`). Якщо такого каталогу ще немає, Docker створить його автоматично.

5. **Як здійснюється відображення мережевих портів?**  
   За допомогою параметра `-p <зовнішній_порт>:<внутрішній_порт>` під час запуску `docker run` (наприклад, `-p 8080:8000` перенаправляє запити з порту 8080 віртуальної машини на порт 8000 усередині контейнера). Інструкція `EXPOSE` у Dockerfile лише документує порт, який слухає програма.

6. **Чим відрізняються команди `docker build` та `docker run`?**  
   Команда `docker build` читає `Dockerfile` і **створює образ (image)**. Команда `docker run` бере готовий образ, **створює з нього контейнер і запускає його**.

7. **Чому застосунок доцільно запускати від непривілейованого користувача?**  
   Із міркувань безпеки (принцип найменших привілеїв). Якщо зловмисник знайде вразливість у вебзастосунку, запущеному від `root`, він отримає повні права всередині контейнера і потенційно зможе скомпрометувати хост-систему. Запуск від користувача `web` мінімізує такі ризики.

8. **Яке призначення інструкції `HEALTHCHECK`?**  
   Вона дозволяє Docker періодично перевіряти, чи дійсно застосунок усередині контейнера працює коректно (наприклад, чи відповідає вебсервер за маршрутом `/health`), а не просто перевіряти, чи запущений процес в ОС. Результат відображається в `docker ps` у вигляді статусу `(healthy)` або `(unhealthy)`.

9. **Чим відрізняються операції зупинення та видалення контейнера?**  
   Зупинення (`docker stop`) завершує головний процес контейнера, але сам контейнер, його файлова система та логи залишаються на диску (його можна запустити знову через `docker start`). Видалення (`docker rm`) повністю знищує контейнер та всі його тимчасові дані з диска.

10. **Як здійснити повернення до попередньої версії застосунку?**  
    Оскільки попередній образ залишився збереженим локально, достатньо видалити поточний контейнер (`sudo docker rm -f lifedays`) і запустити новий контейнер із зазначенням попереднього тегу образу (`lifedays:1.0`):
    ```bash
    sudo docker run -d --name lifedays -p 8080:8000 lifedays:1.0
    ```
